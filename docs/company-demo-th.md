# คู่มือเดโมบริษัท — River Life / Unicorn Cruise

## เปิดระบบ

รัน `./scripts/start-company-demo.ps1` จาก PowerShell ที่โฟลเดอร์โปรเจกต์ แล้วเปิด **http://127.0.0.1:3320/booking**

ระบบนี้เป็น Compose project `riverlife-company-demo` มีฐานข้อมูลแยกและเก็บข้อมูลไว้ข้ามการปิดเปิด ไม่ใช้ `.env` หรือคีย์ชำระเงิน/SMTP ของเว็บหลัก พอร์ต 3000 เป็นระบบหลักที่แยกข้อมูลจากเดโม บัญชีและรหัสผ่านด้านล่างเป็นข้อมูลสำหรับเดโมในเครื่องเท่านั้น

| หน้าที่ | บัญชี | รหัสผ่านเดโม |
|---|---|---|
| ลูกค้าคนที่ 1 | demo-a@example.test | DemoOnly-2026! |
| ลูกค้าคนที่ 2 | demo-b@example.test | DemoOnly-2026! |
| ผู้ดูแล | demo-admin@example.test | DemoOnly-2026! |

เปิดคนละ browser profile/incognito เพื่อแยก session ระหว่างลูกค้ากับแอดมิน บัญชีใช้การเข้าสู่ระบบอีเมล/รหัสผ่านตามปกติ ไม่ต้องใช้ Google หรือ LINE ในการสาธิตนี้

หยุดเดโมด้วย `docker compose -p riverlife-company-demo -f scripts/company-demo.compose.yaml stop` เปิดใหม่ด้วยสคริปต์เดิม ไม่ต้องลบ volume ถ้าต้องการเก็บรายการสาธิตไว้

## บทพูดและลำดับสาธิต 5–7 นาที

1. **เปิดเรื่อง:** “ลูกค้าจองที่นั่งบนเรือ พร้อมเลือกมื้อพิเศษได้ในที่เดียว ข้อมูลที่เห็นวันนี้เป็นตัวอย่างสำหรับสาธิตทั้งหมด ยังไม่ใช่รอบหรือราคาที่เปิดขายจริง”
2. **เลือกที่นั่ง:** เลือกรอบ `[DEMO]` แล้วเลือก “เลือกเป็นรายเก้าอี้” จำนวน 1 คน → โต๊ะ U01 → เก้าอี้ 3 แสดงว่าลูกค้าไม่จำเป็นต้องเหมาทั้งโต๊ะ และอาจร่วมโต๊ะกับผู้อื่น
3. **เติมมื้อพิเศษ:** ชี้แจงว่าบุฟเฟ่ต์รวมแล้ว เพิ่มซีฟู้ดตัวอย่าง 1 รายการและไวน์ 1 รายการ หรือข้ามได้ แสดงยอด 2,100 + 600 + 1,400 = **4,100 บาท (ตัวอย่าง)**
4. **ตรวจรายการ:** ตรวจหมายเลขเก้าอี้ จำนวนคน รายการเสริม และชื่อก่อนสำรอง อธิบายว่าระบบคำนวณยอดและตรวจเก้าอี้ว่างจากเซิร์ฟเวอร์
5. **หลังบ้าน:** เปลี่ยนไปบัญชีแอดมิน `/dashboard` เลือกรายการ DEMO ตรวจยอด ใส่ reference เช่น `DEMO-20261103-001` ที่ไม่ซ้ำและยอด 4,100 บาท จากนั้นยืนยันเพื่อจำลองการออกตั๋ว **ย้ำว่ายืนยันด้วยเงินสมมุติได้เฉพาะระบบเดโมแยกนี้เท่านั้น**
6. **ดูตั๋ว:** กลับบัญชีลูกค้า `/orders` เปิดรายละเอียด เห็นตั๋ว QR 1 ใบตรงเก้าอี้ U01:3 พร้อมรายการอาหาร/ไวน์ มีคิวอีเมลสองฉบับ แต่ระบบเดโมปิดการส่งจริง
7. **กันจองซ้ำ:** ใช้สองบัญชีเลือกเก้าอี้เดียวกันก่อนกดสำรอง คนที่จองไม่ทันจะถูกปฏิเสธและกลับไปเลือกเก้าอี้อื่นได้โดยไม่ต้องกรอกชื่อใหม่ คนละเก้าอี้ในโต๊ะเดียวกันจองแยกได้

เก้าอี้พักไว้ 15 นาที รายการที่ยังไม่ยืนยันยกเลิกได้จากบัญชีลูกค้า รายการที่ยืนยันแล้วไม่คืนที่นั่งเอง ห้ามล้างฐานข้อมูลเพื่อสาธิตซ้ำ ใช้เก้าอี้ว่างหรือสร้างรอบ DEMO ใหม่ ระบบจำกัดการกักที่นั่งหนึ่งรายการต่อบัญชีและสามครั้งต่อ 15 นาที อย่าปิดมาตรการนี้เพื่อเดโม

## สิ่งที่แสดงได้กับสิ่งที่ยังไม่ควรรับปาก

- แสดงได้: การจองเก้าอี้เดียว อาหาร/ไวน์เสริม ยอดจากเซิร์ฟเวอร์ การกันที่นั่งซ้ำ การยืนยันจำลอง ตั๋ว QR และคิวส่งอีเมล
- รอบ/ราคา/ผัง/ภาพสินค้า/จำนวนขายในเดโมเป็นข้อมูลตัวอย่าง ไม่ใช่การรับรองจาก Unicorn
- มีโค้ด Omise PromptPay Sandbox แต่เดโมชุดนี้ปิด gateway ไม่ได้พิสูจน์การจ่ายเงินผ่าน Omise หรือรับเงินจริง
- อีเมลอยู่ในคิว ไม่ได้ส่งถึงกล่องจดหมายจริงในเดโมนี้
- วันที่รอบตัวอย่างตั้งเป็นอีก 7 วันจากวันเตรียม ไม่ใช่ตารางเดินเรือจริง

## ข้อมูลที่ต้องขอจากเจ้าของเรือก่อนเปิดขาย

| ข้อมูลที่ต้องยืนยัน | รายละเอียดที่ต้องได้ | ผู้อนุมัติ |
|---|---|---|
| รอบเดินเรือ | วันขายจริง เวลาเช็กอิน/ขึ้นเรือ/ออก/กลับ ท่าและหมายเลขท่า วันงดเดินเรือ | ฝ่ายปฏิบัติการเรือ |
| ผังและเก้าอี้ | ผังแต่ละชั้นที่มีสัดส่วนและเลขโต๊ะ/เก้าอี้ จำนวนที่นั่ง ทางเดิน เวที บุฟเฟ่ต์ จุดห้ามขาย | ผู้จัดการเรือ |
| กติกาจองรายที่นั่ง | ร่วมโต๊ะกับผู้อื่นได้หรือไม่ เลือกที่ติดกันได้ไหม เด็ก/ทารกใช้ที่นั่งอย่างไร มีโต๊ะเหมาหรือไม่ | ผู้จัดการ/ฝ่ายขาย |
| ราคาที่อนุมัติ | ต่อเก้าอี้และต่อโต๊ะ ภาษี/ค่าบริการ เด็ก/ผู้ใหญ่ โปรโมชั่น และช่วงวันพิเศษ | ผู้มีอำนาจอนุมัติราคา |
| บุฟเฟ่ต์ที่รวม | เมนูที่รวม เครื่องดื่ม ข้อยกเว้น อาหารแพ้/มังสวิรัติ และเงื่อนไขเปลี่ยนเมนู | ฝ่ายอาหาร |
| รายการเสริม | ชื่อและรูปที่อนุญาตให้ใช้ ปริมาณต่อจาน/ขวด ราคา สต็อกต่อรอบ เวลาปิดรับและเงื่อนไขไวน์ | ฝ่ายอาหาร/ฝ่ายขาย |
| ชำระเงิน | บัญชีผู้รับเงิน/ผู้ให้บริการที่เลือก สิทธิ์ผู้ตรวจยอด อายุการพักที่นั่ง การจัดการยอดเข้าหลังหมดเวลา | การเงิน |
| คืนเงิน/เลื่อนรอบ | ลูกค้ายกเลิก เรือยกเลิก ฝน/เหตุสุดวิสัย มาสาย ไม่มา เปลี่ยนคน/ที่นั่ง | ผู้บริหาร/ปฏิบัติการ |
| ตั๋วและอีเมล | ชื่อแบรนด์/โลโก้ ผู้ส่ง อีเมลติดต่อ เนื้อหา เงื่อนไขขึ้นเรือ การส่งซ้ำ | เจ้าของแบรนด์ |
| สิทธิ์และการดูแลข้อมูล | รายชื่อ admin/sales/operator นโยบายเก็บข้อมูลและช่องทางรับเรื่องลูกค้า | เจ้าของระบบ |

ควรขอเอกสารหรือข้อความอนุมัติที่ระบุผู้รับรองและวันที่ เริ่มด้วยรอบจริงหนึ่งรอบที่ข้อมูลครบ ทดสอบตามข้อมูลนั้นก่อนเปิดขาย และคงข้อมูลที่ยังไม่ยืนยันเป็นฉบับร่าง
