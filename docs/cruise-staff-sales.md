# ฝ่ายขาย: จองรายเก้าอี้ Unicorn

- `/sales` ใช้ผังและรายการเสริมเดียวกับ `/booking` เลือกรอบ เก้าอี้ อาหาร/ไวน์ แล้วตรวจยอดก่อนสำรอง
- ลูกค้าต้องมีบัญชีผู้ใช้แล้ว ใช้อีเมลบัญชีลูกค้าเพื่อผูกเจ้าของรายการและผู้รับอีเมล ไม่สร้างบัญชีแทนโดยอัตโนมัติ
- หลังสำรอง เซลได้รับลิงก์ `/booking?payment=<id>` ให้ลูกค้าเข้าสู่ระบบชำระเองภายในเวลาพักที่นั่ง เซลไม่สามารถใช้ลิงก์นี้อ่านข้อมูลส่วนตัวหรือจ่ายแทนผ่านสิทธิ์ของลูกค้า
- API ใหม่ GET/POST `/api/v1/dashboard/sales/cruises/reservations` อนุญาต sales/admin เท่านั้น รายการขายแสดงเฉพาะที่ผู้ใช้คนนั้นสร้าง ล่าสุด 100 รายการ
- ราคาจาก server, inventory lock, hold budget, idempotency, ตั๋วและอีเมล ใช้เส้นทางเดิมของ cruise reservation
- `sales_user_id` บันทึกพร้อม reservation ภายใน transaction; การเรียก API ลูกค้าปกติไม่สามารถกำหนดค่านี้เอง
- รายการโซนเดิมยังเปิดดูได้จากส่วนพับ ไม่มีฟอร์มสร้างรายการโซนใหม่ในหน้าฝ่ายขาย
- `/checkout` และ `/table-preview` นำไป `/booking` พร้อม query string เดิม ส่วน payment/tickets ของรายการเก่ายังคงไว้เพื่อไม่ทำลายประวัติ

การตรวจ: Go integration tests กับ PostgreSQL/Redis แยก ตรวจเจ้าของรายการ, เซลอื่น, operator/user, ราคาปลอม, retry, ชนเก้าอี้, คนละเก้าอี้โต๊ะเดียวกัน และตั๋วถึงลูกค้า; Playwright ตรวจฝ่ายขายทั้ง 390/1440px พร้อมบริการเสริมและลิงก์ชำระ รวมถึงหน้าเดินทาง/help/entry routes
