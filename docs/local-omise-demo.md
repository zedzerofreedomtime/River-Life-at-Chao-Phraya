# รอบ DEMO สำหรับทดสอบหน้าชำระเงิน

วันที่ 3 พฤศจิกายน 2569 ผู้ใช้อนุญาตให้ใช้รอบ DEMO เชื่อม Omise Sandbox ในเว็บหลัก หลังพบว่าไม่มีรอบ published จึงเข้าหน้าผังทดลองและไม่มีขั้นชำระเงิน

สร้างด้วย `scripts/enable-local-omise-demo.ps1` โดยตรวจ local demo mode, sandbox config และชื่อฐานข้อมูลก่อน พร้อมสำรอง pg_dump แบบ custom และตรวจอ่าน archive ก่อนเพิ่มข้อมูล

- รอบ `demo_omise_20261103` มีคำว่า DEMO และไม่ใช่รอบขายจริง
- วัน 10 พฤศจิกายน 2569 เวลา 19:00 เป็นวันตัวอย่าง ไม่ใช่วันที่เจ้าของเรือยืนยัน
- โต๊ะตัวอย่าง 16 โต๊ะ / เก้าอี้ 64 ตัว เลือกรายเก้าอี้ได้ ราคาชั้นบน 1,200 บาท/เก้าอี้ และชั้นล่าง 1,000 บาท/เก้าอี้เป็นราคาทดสอบ
- อาหารตัวอย่าง 600 บาท ไวน์ตัวอย่าง 1,400 บาท
- รอบฉบับร่างเดิมยังคงเดิม ไม่มีการเพิ่มสิทธิ์ผู้ใช้หรือปิด validation

ขั้นตอน: เปิด `/booking` → เลือกรอบ DEMO → เลือกเก้าอี้ → อาหาร/ไวน์ → กรอกชื่อและยืนยันสำรอง → ยอมรับยอดในหน้า Omise → สร้าง QR ทดสอบ

ตรวจจริงด้วยบัญชีที่เข้าสู่ระบบบนเว็บไซต์: U01:1 จำนวน 1 คน + อาหาร 600 + ไวน์ 1,400 = 3,200 บาท บันทึกเข้าฐานข้อมูลเป็น 120000 + 200000 = 320000 สตางค์ และได้ charge จาก Omise ที่เป็น `chrg_test_...` พร้อมภาพ QR Test Mode สถานะ pending ยังไม่ได้จำลองจ่ายเงินหรือออกตั๋วในการตรวจรอบนี้ รายการทดสอบจะหมดเวลาตาม hold เดิม ไม่เปลี่ยนเวลาหรือสถานะเพื่อบังคับให้ผ่าน

หน้ารายการจองของฉันใช้กลับไปเปิดการชำระเงินของรายการเดิมได้ การสร้าง QR ไม่ใช่การชำระสำเร็จ ต้องใช้ Omise Test Dashboard จำลองผลแล้วรอระบบตรวจยืนยัน ห้ามโอนเงินจริง

แก้ข้อความเก่าใต้ปุ่มจองที่ระบุว่ายังไม่เปิด Gateway ให้สื่อว่าขั้นชำระเงินอยู่หลังยืนยันสำรอง และแก้คำอธิบายการออกตั๋ว/อีเมลให้ตรงกับการตรวจยืนยันของระบบ

ผลทดสอบที่เกี่ยวข้อง: Playwright `omise-payment.spec.ts`, `individual-chairs.spec.ts`, `booking-recovery.spec.ts` รวม 8 ผ่าน / 0 ไม่ผ่าน / 0 ข้าม โดยกรณี Omise ในชุดอัตโนมัติใช้ mocked API; การสร้าง QR จริงตรวจผ่าน browser และฐานข้อมูลแยกต่างหาก Build ผ่านพร้อม typecheck ที่เป็นส่วนหนึ่งของ build
