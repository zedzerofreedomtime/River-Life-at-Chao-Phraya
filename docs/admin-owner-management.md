# Owner และงานหลังบ้าน River Life

## สิทธิ์
- Owner เข้าเมนู Admin/Sales/Operator ได้ จัดการสิทธิ์ Admin และอนุมัติคืนเงิน Sandbox
- Admin จัดการลูกค้า Sales/Operator ได้ แต่เปลี่ยนสิทธิ์/ระงับ/ตัดเซสชัน Owner หรือ Admin ไม่ได้
- ห้ามเปลี่ยนสิทธิ์ ระงับ หรือตัดเซสชันตัวเองผ่านเมนูจัดการ; บัญชี Owner ถูกป้องกันจากการเปลี่ยนโดยเมนูนี้ ต้องใช้การจัดการบัญชีโดยผู้ดูแลระบบหากจะโอนเจ้าของ
- การเปลี่ยนบทบาท ระงับ/เปิดบัญชี และ force logout เพิ่ม auth_version เพื่อให้ cookie ทุกอุปกรณ์หมดสิทธิ์ ตรวจ suspended ในทุกการอ่านและสร้าง session
- รหัสผ่านเข้ารหัส bcrypt ไม่ส่งกลับใน API; ปุ่มรีเซ็ตเรียกกระบวนการ OTP เดิมไปอีเมลเจ้าของบัญชี แอดมินไม่รับ OTP แทน

## หน้าจัดการใหม่ /dashboard
- ค้นหาผู้ใช้จากฐานข้อมูล แบ่งหน้า 50 รายการ; ไม่จำกัดค้นหาแค่ 200 รายการในเบราว์เซอร์
- ระงับ/เปิดบัญชี ตัดเซสชัน เปลี่ยนบทบาท และส่ง OTP ตั้งรหัสผ่านใหม่
- ส่งอีเมล booking/tickets ของรายการ confirmed ใหม่ไปผู้รับเดิม ใช้ payload และ Ticket ID เดิม จำกัดการส่งซ้ำหลังส่งสำเร็จอย่างน้อย 1 นาที ไม่ใช่รับประกัน SMTP exactly-once
- ประวัติรวม staff_audit และ cruise_admin_audit แบ่งหน้า
- รายงานยอดยืนยันตามวันที่สร้างรายการ (เวลาไทย) แยกรอบ เซล/web และ Omise/manual พร้อม CSV; ไม่ใช่ยอดเงินสุทธิหลังค่าธรรมเนียมและไม่ใช่กำไร จำกัดสูงสุด 1,000 กลุ่มต่อช่วงค้นหา

## การย้ายเก้าอี้
รอบเดิม ราคาเก้าอี้รวมเท่าเดิม จำนวนเท่าเดิม ยังไม่เช็กอิน และไม่อยู่ระหว่างคืนเงินเท่านั้น ตรวจที่นั่งว่างและ lock ใน transaction ไม่ชนคนอื่น ออก Ticket ID ใหม่เพื่อยกเลิก QR เก่า ปรับ payload และเข้าคิวอีเมลใหม่ทั้ง 2 ชนิด
กรณีเปลี่ยนราคา/ย้ายคนละรอบยังถูกปฏิเสธ ต้องกำหนดการเก็บ/คืนส่วนต่างก่อนเปิดใช้

## คืนเงิน
เฉพาะ Owner เต็มจำนวนผ่าน Omise Sandbox ของรายการ confirmed ที่ไม่มีการเช็กอินและไม่มี partial refund เดิม ตรวจ charge/metadata/ยอด/currency/livemode จาก provider ก่อน POST
บันทึก intent ในฐานข้อมูลก่อนเรียก Omise คำขอซ้ำไม่คืนซ้ำ หากผลไม่แน่ชัดให้กดตรวจรายการเดิม ระบบ GET ตรวจ refunded_amount และจะไม่ POST ครั้งที่สอง หาก provider ปฏิเสธ 4xx บันทึก rejected หากไม่แน่นอนคง review และระงับการเช็กอินจนตรวจผลสำเร็จ
หลังยืนยันคืนสำเร็จเปลี่ยนรายการเป็น cancelled และปล่อยที่นั่ง QR เดิมเช็กอินไม่ได้ รายการที่โอนนอก Gateway และการคืนบางส่วนยังไม่รองรับ
API ยังจำกัด test keys เท่านั้น การรองรับคืนเงินของแต่ละช่องทางขึ้นกับ Omise; คำขอคืนที่ provider ปฏิเสธจะไม่ถูกแสดงว่าสำเร็จ
อ้างอิง API: https://docs.omise.co/refunds-api

## การตรวจ
Go integration ใช้ PostgreSQL/Redis แยก: บทบาท Owner/Admin, self/protected-account, suspend/version, audit/search, จองรายเก้าอี้/เมนู, move occupied/invalid chairs, เปลี่ยน QR, resend ID เดิม, refund owner-only/success/repeated/unknown-result reconciliation และ HTTP refund response validation
Playwright ตรวจ 390/1440px สำหรับ Owner/Admin รวม regression booking และ Sales; flow เขียนข้อมูลใช้ mock ข้อมูลจำลอง
บัญชีทดสอบใหม่ 4 บัญชีสร้างเฉพาะเครื่องนี้ รหัสผ่านสุ่มอยู่ในไฟล์นอก repository ไม่ใช่บัญชีสำหรับเปิดขายจริง
